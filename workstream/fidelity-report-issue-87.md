## 2. Human-Readable Summary

This PR adds three new commands (`memo bank init`, `memo bank list`, `memo bank show`) and a new "banks" view inside the existing `memo inspect` command. `bank init` creates a bank the first time someone uses it, by writing one memory entry — there's no separate "create a bank" registration step, matching how the product was designed to work. Running `init` twice on the same bank is safe: the second run changes nothing and just reports what's already there. `bank list` and `bank show` give counts of how much memory each bank holds, broken out by category and status (active/archived/superseded). The `inspect` command's existing views (organizations, repositories, domains) were not touched or altered in any way — the new "banks" view was added alongside them without changing their behavior.

All three open design questions the pre-implementation test plan flagged were resolved exactly as the spec's clarification table said they should be, and are now covered by dedicated tests: a second `--set-default` call rewrites the config unconditionally, per-bank counts are broken down by both category and status (not collapsed), and the new "banks" view always shows up regardless of other filtering flags. The mechanism `bank init` uses to reuse the existing write logic was checked closely for safety (a common source of test-pollution bugs) and found clean: it temporarily and locally intercepts one write call on a single-use connection object, restores it immediately afterward, and never touches the shared write code itself — confirmed by a zero-line diff on that file.

Two documentation locations were intentionally left for a later, already-planned story rather than updated here, and that deferral is legitimate and pre-scoped in the spec itself, not a hidden gap. One very small, low-risk documentation staleness item was found (a project-tree table missing a few command names) and is unrelated to this story's own scope — it predates this PR and affects several other already-shipped commands equally.

Two scrutiny items called out in the audit brief were independently verified structurally (not just via test assertion) and found compliant:

1. **`bank init` → `write.ts` delegation mechanism:** confirmed clean by direct diff read — `git diff origin/integration/prd-004-phase-2-banks-kinds-sessions-recall...origin/story/S2-08-bank-inspect-facet -- src/commands/write.ts` returns **zero lines**, i.e. `write.ts` is genuinely untouched. The delegation in `handleBankInit` monkeypatches only the local, per-call `qdrant.upsert` instance property (not the class prototype) on a `QdrantRepository`/fake instance created fresh inside that single invocation, and restores it in a `finally` block before returning. Because each call creates its own repository instance, there is no possibility of the override leaking across calls or across tests. `self_id` capture is reliable: it reads the `id` argument passed to `upsert(id, vector, payload)`, independently confirmed (via `src/commands/write.ts:480`, `qdrant.upsert(finalPayload.id, vector, finalPayload)`) to be the entry's own id.
2. **§18.14 items 11/12/13:** all three landed exactly as resolved in the spec's clarification table, confirmed by direct code inspection (not just test assertion) as detailed in the Per-AC table above and the extension-additivity check on `aggregateMultipleFields`.
